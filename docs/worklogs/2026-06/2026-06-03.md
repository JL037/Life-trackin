## Session 2
- **Date**: 2026-06-03
- **Agent**: Cascade
- **Focus**: Fix AT Protocol OAuth — confidential client migration

### Problem
Logging in with a real Bluesky handle returned **HTTP 500** with backend log:
```
PAR request failed (HTTP 400): invalid_request
```

### Root Cause Analysis
The Indigo SDK's `PushedAuthRequest` struct (`atproto/auth/oauth/types.go:282-315`) uses plain `string` fields (not pointers) for `client_assertion_type` and `client_assertion`. For public clients (`NewLocalhostConfig`), these fields remain empty and `go-querystring` encodes them as:
```
client_assertion=&client_assertion_type=
```
Bluesky's auth server rejects this as `invalid_request`.

### Decision
Switch from **public localhost client** to a **confidential client** using `NewPublicConfig` + `SetClientSecret` with a P-256 ECDSA keypair. This is the production-grade approach used by apps like `plyr.fm`.

### Changes Made
1. **`backend/internal/auth/oauth.go`**
   - `NewOAuthApp` now takes `privateKeyMultibase string` parameter
   - Uses `oauth.NewPublicConfig(clientID, callbackURL, scopes)` with `client_id = APP_URL + "/client-metadata.json"`
   - Parses private key via `atcrypto.ParsePrivateMultibase()`
   - Calls `config.SetClientSecret(privKey, "lifetrack-key-1")`
   - Returns `(*oauth.ClientApp, error)` instead of `*oauth.ClientApp`

2. **`backend/internal/handlers/auth.go`**
   - `ClientMetadata` handler injects JWKS: `meta.JWKS = &h.app.Config.PublicJWKS()`

3. **`backend/cmd/server/main.go`**
   - Reads `OAUTH_PRIVATE_KEY` from env, fatals if missing
   - Passes key to `auth.NewOAuthApp`, handles init error

4. **`backend/.env.example`**
   - Added `OAUTH_PRIVATE_KEY` with generated P-256 multibase key

5. **`backend/go.mod`**
   - Updated `go 1.22` → `go 1.26` (required by Indigo SDK)

## Session 3

- **Agent**: Cascade
- **Focus**: Correct root cause, revert unnecessary confidential client migration

### Problem
OAuth login still failed after confidential client migration. New error from Bluesky:
```
Use of "localhost" hostname is not allowed (RFC 8252),
use a loopback IP such as "127.0.0.1" instead at body.redirect_uri
```

### Root Cause (Corrected)
The **real** bug is in the Indigo SDK itself:
- `InitialTokenRequest` (token exchange) correctly uses `*string` with `omitempty` for `client_assertion_type` and `client_assertion`
- `PushedAuthRequest` (PAR step) incorrectly uses plain `string` without `omitempty`
- For public clients (`NewLocalhostConfig`), these fields remain empty strings and `go-querystring` encodes them as:
  ```
  client_assertion=&client_assertion_type=
  ```
- Bluesky's auth server rejects this as `invalid_request`

The confidential client migration was a red herring. It would work for production (public HTTPS URL), but for local dev we don't need it.

### Solution
1. **Patch the Indigo SDK** to match `InitialTokenRequest`'s pattern:
   - `types.go`: `string` → `*string` with `omitempty` for both fields
   - `oauth.go`: assign pointers (`&ClientAssertionJWTBearer`, `&assertionJWT`)

2. **Revert to `NewLocalhostConfig`** (public client, virtual metadata — no public URL needed)

3. **Switch `localhost` → `127.0.0.1`** everywhere (Bluesky's RFC 8252 requirement)

### Changes Made
1. **`docker/patch-indigo.sh`** (new)
   - Applies the SDK patch in both host and container module caches

2. **`docker/backend.Dockerfile`**
   - Runs `patch-indigo.sh` after `go mod download`

3. **`backend/internal/auth/oauth.go`**
   - Reverted to `NewLocalhostConfig` with `appURL+"/api/auth/callback"`
   - Removed private key parsing and `SetClientSecret`

4. **`backend/internal/handlers/auth.go`**
   - Reverted `ClientMetadata` to not inject JWKS

5. **`backend/cmd/server/main.go`**
   - Reverted to simple `auth.NewOAuthApp(appURL, pool)` call
   - Removed `OAUTH_PRIVATE_KEY` env var check

6. **`backend/.env`** and **`backend/.env.example`**
   - `APP_URL=http://127.0.0.1:8080`
   - `FRONTEND_URL=http://127.0.0.1:5173`
   - Removed `OAUTH_PRIVATE_KEY`

7. **`docker-compose.yml`**
   - `APP_URL=http://127.0.0.1:8080`
   - `FRONTEND_URL=http://127.0.0.1:5173`
   - Removed `OAUTH_PRIVATE_KEY`
